# Releasing CatKeyper

CatKeyper releases are published automatically by GitHub Actions when a maintainer pushes a semantic version tag.

The release workflow:

- validates the tag name
- extracts the version from the tag
- runs tests
- builds ZIP and DMG artifacts with `make release VERSION=<version>`
- extracts matching release notes from `CHANGELOG.md`
- creates a GitHub Release
- uploads the ZIP and DMG assets

## Prerequisites

- Push access to `https://github.com/DooD73/catkeyper`
- A clean `main` branch containing the changelog entry for the version being released
- A tag in the format `vX.Y.Z`, for example `v1.1.0`

No personal access token is required. The release workflow uses the built-in `GITHUB_TOKEN` with `contents: write`.

## 1. Prepare the changelog

Move release-ready items from `Unreleased` into a versioned section. The parser expects a second-level heading for the version:

```markdown
## [1.1.0] - 2026-07-01

### Added

- New release item
```

The parser also accepts `## [v1.1.0] - 2026-07-01`, but the unprefixed SemVer form is preferred.

If the matching section is missing or empty, the workflow publishes fallback notes of `Release vX.Y.Z` and emits a warning.

## 2. Commit the release notes

```bash
git switch main
git pull --ff-only
git add CHANGELOG.md
git commit -m "update changelog for v1.1.0"
git push origin main
```

Skip the commit if the changelog entry is already on `main`.

## 3. Create and push the release tag

Use an annotated tag:

```bash
git tag -a v1.1.0 -m "v1.1.0"
git push origin v1.1.0
```

Pushing the tag starts `.github/workflows/release.yml`.

## 4. Monitor the workflow

Open the repository Actions tab and watch the `Release` workflow for the tag.

The workflow should produce:

- `build/catkeyper-<version>-macos.zip`
- `build/catkeyper-<version>-macos.dmg`
- `build/catkeyper-macos.zip`
- `build/catkeyper-macos.dmg`

When the job succeeds, GitHub Releases will contain a published release named after the tag, with versioned artifacts and stable latest-download aliases attached.

## 5. Verify the published release

Download the latest assets from:

- `https://github.com/DooD73/catkeyper/releases/latest/download/catkeyper-macos.zip`
- `https://github.com/DooD73/catkeyper/releases/latest/download/catkeyper-macos.dmg`

If using the versioned asset filenames generated by the workflow, download them from the release page for the tag.

On a clean Mac or VM:

1. Open `CatKeyper.app`.
2. Confirm the Accessibility permission flow works.
3. Lock keyboard input from the menu bar.
4. Unlock with the menu bar button.
5. Lock again and unlock with the Shift+CAT chord.

## Dry-run testing

The workflow contains a `DRY_RUN` environment variable. Temporarily set it to `"true"` in `.github/workflows/release.yml` on a test branch if you need to validate version parsing, changelog extraction, tests, and artifact generation without creating a GitHub Release.

Return `DRY_RUN` to `"false"` before merging.

## Troubleshooting

- `Release tags must match vX.Y.Z`: create a tag like `v1.1.0`; prerelease and build metadata tags are not accepted by the current workflow.
- `Expected release asset ... was not created or is empty`: inspect the `make release` output. The workflow expects the Makefile to create both ZIP and DMG files using the parsed version.
- `GitHub Release ... already exists`: delete the existing release or create a new SemVer tag.
- Missing changelog notes: add a `## [X.Y.Z] - YYYY-MM-DD` section to `CHANGELOG.md` and tag again with a new version.
